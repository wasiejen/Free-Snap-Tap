# gemini answer

The context invalidation and cache re-fill is happening because of a **race condition between `tool.execute.after` and OpenCode’s active generation loop**, compounded by how `promptAsync` mutates the active message tree.

---

### Root Cause: Why it invalidates "sometimes"

`tool.execute.after` fires as soon as a tool completes execution on the server. However, in OpenCode's internal lifecycle, the LLM turn is **not finished yet** when this hook executes.

1. **Race Condition (Active Stream):** When `tool.execute.after` fires, the agent loop is still actively processing the tool output to construct the next response chunk or tool call.
2. **Context Branching:** Calling `ns.promptAsync()` directly while the session state is technically **BUSY** forces OpenCode to append a new synthetic message directly onto the message history array.
3. **KV Cache Busting:**
* **When it works cleanly:** The tool output happens to finalize before `promptAsync` resolves. The text gets appended safely at the end of the turn as a continuation prompt.
* **When it causes a full refill:** `promptAsync` executes *while* the parent completion request is still open or mid-assembly. Interposing a new message into the array changes the sequence prefix, invalidating the backend KV cache in `llama.cpp` and forcing the server to re-evaluate the entire context history from token 0.



---

### The Fix: Wait for Session Idle or Use Delayed Dispatch

To stop context invalidation, your nudge must **never execute mid-turn while the engine is busy**. You have two architectural options to fix this:

#### Solution 1: Defer the Nudge until the Agent goes Idle (Recommended)

Instead of dispatching `promptAsync` synchronously inside `tool.execute.after`, check if the session is idle, or wait for the turn boundary to complete.

```typescript
function deliverNudge(sid: string, rung: number, text: string): void {
  try {
    const ns = client?.session;
    
    // 1. Defer execution to the next event loop tick so the current tool output flushes
    setImmediate(async () => {
      try {
        // 2. Optional: Verify session state isn't actively generating
        // If your OpenCode SDK client provides session status checking:
        const status = await ns?.status?.({ path: { id: sid } });
        if (status?.type === "busy") {
          // If busy, delay until idle or skip to avoid cache-invalidation
          return;
        }

        const fn = ns?.promptAsync;
        if (typeof fn !== "function") return;

        await fn.call(ns, { 
          path: { id: sid }, 
          body: { parts: [{ type: "text", text, synthetic: true }] } 
        });
      } catch (e) {
        // Handle background errors
      }
    });

  } catch (e) {
    // Sync error handling
  }
}

```

---

#### Solution 2: Mutate the Tool Result Instead of Injecting a New Message

If your goal is simply to "nudge" the agent with its current context usage right after a tool completes, **appending the nudge directly to the tool's execution result** avoids sending a separate `promptAsync` request entirely.

Modifying the tool output in-place keeps the message sequence linear and **100% preserves the KV cache**:

```typescript
// Inside your plugin hook definition:
export const plugin = {
  "tool.execute.after": async (input, output) => {
    // Inject the context nudge directly into the tool output string
    const nudgeText = `\n\n[Context System Nudge: Current Context Usage Rung ${rung}]`;
    
    if (typeof output === "string") {
      return output + nudgeText;
    } else if (output?.content) {
      output.content += nudgeText;
      return output;
    }
    
    return output;
  }
};

```

---

### Summary Recommendation

* **Use Solution 2** if you want the nudge to strictly be part of the tool's immediate output feedback loop. It guarantees **zero context cache invalidation** because it doesn't create a secondary asynchronous message request.
* **Use Solution 1** if the nudge must remain a distinct `synthetic: true` message, but wrap it in an idle check or `setImmediate` deferral so it never collides with an active LLM generation stream.
