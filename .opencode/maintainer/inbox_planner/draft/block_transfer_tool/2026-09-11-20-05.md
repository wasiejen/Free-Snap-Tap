Your skepticism is completely justified! In JavaScript/TypeScript, where you place that variable declaration dictates its lifecycle.

It depends on where the object is defined relative to the tool execution:

   If it is inside the function body: Yes, it resets on every single call, completely wiping the clipboard.

   If it is outside the function body (at file/module scope): No, it does not reset between calls—provided the tool file stays loaded in process memory.

Because clipboardBuffers lives at the module level, Node/Bun keeps it alive in process memory for as long as the OpenCode process runs. When the LLM calls CUT in Turn 1 and PASTE in Turn 2, clipboardBuffers retains its contents.





example python code how block transfer works in pythonS

```py
import re

def block_transfer(src_file: str, dst_file: str, start_marker: str, end_marker: str, target_marker: str = None, mode: str = "MOVE"):
    """
    Moves or copies a block of text between files using start/end line anchors.
    Saves generation tokens by handling the text extraction and insertion locally.
    """
    # 1. Read source
    with open(src_file, 'r', encoding='utf-8') as f:
        src_lines = f.readlines()

    # 2. Find start and end line indices using fuzzy/unique line prefixes
    start_idx = next(i for i, line in enumerate(src_lines) if start_marker in line)
    end_idx = next(i for i, line in enumerate(src_lines) if i >= start_idx and end_marker in line)

    # Extract the block
    extracted_block = src_lines[start_idx : end_idx + 1]

    # 3. Handle DELETE or MOVE (cut from source)
    if mode in ["MOVE", "DELETE"]:
        new_src_lines = src_lines[:start_idx] + src_lines[end_idx + 1:]
        with open(src_file, 'w', encoding='utf-8') as f:
            f.writelines(new_src_lines)

    if mode == "DELETE":
        return f"Successfully deleted lines {start_idx+1} to {end_idx+1} from {src_file}."

    # 4. Handle PASTE into target file
    with open(dst_file, 'r', encoding='utf-8') as f:
        dst_lines = f.readlines()

    if target_marker:
        insert_idx = next(i for i, line in enumerate(dst_lines) if target_marker in line)
    else:
        insert_idx = len(dst_lines)  # Default to append at end

    # Insert extracted block
    new_dst_lines = dst_lines[:insert_idx] + extracted_block + dst_lines[insert_idx:]
    with open(dst_file, 'w', encoding='utf-8') as f:
        f.writelines(new_dst_lines)

    return f"Successfully moved {len(extracted_block)} lines from {src_file} to {dst_file}."
```

#### 1. Context Maintenance (`compact_memory`)
* **When to call:** Execute `compact_memory` immediately after completing a heavy file-ingestion phase, a multi-file analysis, or a major task milestone. 
* **Why:** Frees context window memory and keeps response times fast.
* **Post-Compaction Rule:** If you need specific task rules after compaction, follow system section SECTION_TASK_RELOAD and re-read the target task file via `read_file`.

#### 2. File & List Housekeeping (`block_transfer`)
* **Mandatory Rule:** NEVER use `write_file` or `str_replace` to move, copy, delete, or organize multi-line blocks, TODO lists, or log sections. ALWAYS use `block_transfer`.
* **Modes:**
  * Use `MOVE` to instantly transfer a block from a source file to a destination file using unique line anchors.
  * Use `CUT` / `COPY` $\rightarrow$ `PASTE` when manipulating multiple buffers across files.
  * Use `DELETE` to purge completed sections without outputting text.
* **Anchor Selection:** Provide short, unique line prefixes for `startMarker` and `endMarker` to slice text cleanly without generating full line contents in your tool call.
